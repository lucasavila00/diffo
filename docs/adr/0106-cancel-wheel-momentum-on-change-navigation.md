# ADR 0106: Cancel wheel momentum on change navigation

Refines [ADR 0014](0014-smooth-scrolling.md),
[ADR 0047](0047-bound-wheel-momentum-for-ssh.md), and
[ADR 0080](0080-whole-change-block-navigation.md).

## Context

Diffo does not animate inertial scrolling. A terminal or trackpad creates
momentum by sending a decaying sequence of wheel events after the physical
gesture ends. The wheel-friction filter from ADR 0047 suppresses the sparse tail
but continues to accept same-direction events while they remain within the 48 ms
active interval.

If the user presses `n` or `p` during that sequence, change navigation correctly
jumps to another committed change block. Wheel events that were already
generated by the earlier gesture can then arrive and move the viewport away from
the selected block. The old gesture wins over the newer, explicit navigation
intent.

Simply resetting wheel friction on `n` or `p` is insufficient: the next tail
event would look like the first event of a fresh burst and would be accepted.

## Decision

When a plain lowercase `n` or `p` key press is routed to Diff change navigation,
cancel the active terminal wheel burst before dispatching that navigation event.
Process the navigation normally and keep its existing atomic target preparation.

While a burst is cancelled:

- reject every subsequent wheel event in the cancelled direction, including
  events inside ADR 0047's 48 ms active interval;
- continue recording the rejected events and updating the last-wheel timestamp
  so the complete terminal-generated tail remains one cancelled burst;
- accept a direction reversal immediately and begin a new burst in that
  direction; and
- after 120 ms without a wheel event, accept the next wheel event as a fresh
  burst.

Apply cancellation in raw event order. If one drained input batch contains wheel
events, `n` or `p`, and more wheel events, preserve wheel movement before the
key, perform the change jump, and reject the wheel events after the key. Do not
pre-scan and discard the complete batch.

Cancel only when the current input context routes the key to the Diff activity's
`JumpToNextChange` or `JumpToPreviousChange` action. Typing `n` or `p` in the
commit editor, command palette, picker, prompt, Explorer, or any other modal or
activity does not change wheel-filter state. Uppercase, modified, release, and
unrelated key events also do not cancel a burst.

Keep this state in the existing input-layer wheel-friction filter. Do not add
momentum or navigation state to the Diff model, schedule a timer, request a
passive redraw, or add configuration, CLI options, environment controls, or new
key bindings. Mouse change-button cancellation is outside this decision.

## Consequences

The most recent explicit keyboard intent wins: after `n` or `p`, stale motion
from the preceding terminal gesture cannot dislodge the selected change. A
deliberate wheel reversal remains responsive, and another same-direction gesture
works after the fixed burst-reset interval.

The input layer needs a read-only indication that the current context will route
a plain `n` or `p` press to Diff change navigation. It must not duplicate
navigation target calculation or inspect pending diff projections.

Filtered tail events remain visible in frame traces, so a trace distinguishes
input received from viewport movement applied. Suppressing them causes no redraw
by itself, preserving the SSH cost boundary from ADR 0047.

## Code change proposal

- Extend `WheelFriction` with a cancelled-burst state and an explicit
  cancellation transition.
- Let the event loop identify only context-valid Diff `n` and `p` navigation
  before filtering each event in order.
- Keep the existing Diff input mapping as the sole producer of navigation
  messages; the wheel filter only decides whether later wheel events are
  accepted.

## Verification

- A deterministic `WheelFriction` test accepts an active same-direction burst,
  cancels it, rejects same-direction events through the tail, accepts an
  immediate reversal, and accepts a fresh same-direction burst after the 120 ms
  reset.
- An ordered-batch test proves wheel events before `n` or `p` remain accepted
  and same-direction events after it are rejected.
- Input-context tests prove modal, picker, prompt, Explorer, uppercase,
  modified, repeat, and release events cannot cancel Diff wheel momentum.
- A frame-traced PTY regression uses a diff with separated change blocks, sends
  a wheel burst, `n` or `p`, and a same-direction tail without sleeps or delay
  hooks, then proves the jump target commits atomically and remains the rendered
  position. The trace retains the rejected raw wheel events and shows no
  tail-only redraw.
- Existing direction-reversal, 48 ms active interval, 120 ms reset, keyboard
  navigation, atomic syntax readiness, and terminal restoration tests continue
  to pass.
- `make all` passes.
